# AI-Powered Farm Assistant 🌱

An AI-assisted crop inspection project that uses a camera and computer-vision models to identify plant parts and help inspect leaves for possible diseases. It is a prototype intended for experimentation and future integration into a smart farm rover.

## What it does

The repository contains several small computer-vision experiments, plus a main camera-based inspection workflow.

### Main inspection workflow (`final2.py`)

- Opens a webcam so you can inspect a plant or crop.
- Uses a custom YOLO model (`sam_model.pt`) to detect the classes learned by that model, intended here to include **leaves, flowers, and fruits**.
- Counts detected leaves, flowers, and fruits in a captured frame.
- Runs a separate PyTorch/ResNet18 classifier (`plant_disease_model_best.pth`) on detected leaf crops to predict a plant-disease class.
- Prints results in English/Hinglish and includes Hindi labels for some disease classes.
- Writes the latest inspection results to `farm_report.json`.
- Attempts to send a crop-result message to a Flask service using `send_crop_message.py`.

**Important:** Fruit ripeness inference is currently disabled in the main scripts. The report includes ripe/raw fruit fields, but those counts should not be treated as active predictions. The disease model can only recognize the classes it was trained on; a prediction is not a definitive diagnosis.

## Project files

| File | Purpose |
|---|---|
| `final2.py` | Main inspection script; camera capture, YOLO detection, leaf disease classification, report saving, and optional Flask message sending |
| `final.py` | Earlier version of the inspection workflow |
| `sam_model.pt` | Custom YOLO weights used for crop-part detection |
| `plant_disease_model_best.pth` | PyTorch checkpoint for the plant-disease classifier |
| `farm_report.json` | Example/latest structured report generated by the main workflow |
| `send_crop_message.py` | Sends a message to a Flask endpoint configured in the script |
| `live_detection.py` | Live object detection using the general `yolo26n.pt` model |
| `counting.py` | Camera-based counting experiment using `sam_model.pt` |
| `capture.py` | Captures a frame, detects objects, and attempts to save an annotated image |
| `detector.py` | Runs general YOLO detection on `photo.jpg` |
| `crop.py` | Experiment for cropping a detected object |
| `camera.py`, `test_camera.py` | Camera testing utilities |
| `data.yaml` | YOLO dataset configuration used during training; its path refers to a training environment and may need updating |
| `yolo26n.pt` | General YOLO model weights used by some experiments |

## Requirements

- Python with a version supported by the installed PyTorch and Ultralytics packages. Python **3.11 or 3.12** is a sensible starting point if you are setting up a fresh environment; check package compatibility for your operating system.
- A webcam or USB camera.
- The model files listed above, present in the project directory.
- Internet access for installing Python packages. GPU/CUDA is optional; the main script automatically selects CUDA when PyTorch detects it, otherwise it uses the CPU.
- For message delivery, a separate Flask service must be running and reachable at the URL configured in `send_crop_message.py`.

## Setup

Open a terminal in the project folder.

### 1. Create and activate a virtual environment

**Windows (PowerShell):**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, you can use Command Prompt instead:

```bat
.venv\Scripts\activate.bat
```

**Linux / macOS:**

```bash
python3.11 -m venv .venv
source .venv/bin/activate
```

### 2. Install dependencies

Upgrade pip first:

```bash
python -m pip install --upgrade pip
```

Install the packages used by the main workflow:

```bash
python -m pip install opencv-python ultralytics torch torchvision pillow
```

PyTorch installation can vary by operating system and GPU. If you need NVIDIA GPU acceleration, follow the official PyTorch installation selector to choose the matching CUDA build.

> Note: The repository's `requirements.txt` appears to be encoded in UTF-16 and may not work directly with `pip install -r requirements.txt` in every environment. The command above installs the core packages used by the main scripts. If you repair the requirements file, you can install from it instead.

### 3. Check the model files

Make sure these files are in the same folder as `final2.py`:

```text
sam_model.pt
plant_disease_model_best.pth
```

The disease checkpoint is loaded as a dictionary containing a `classes` list and a `model_state_dict`. If your checkpoint has a different structure, the loading code will need to be adjusted.

## Run the project

From the project directory, activate the virtual environment and run:

```bash
python final2.py
```

A camera window should open.

- **Press `S`** to analyze the current frame.
- **Press `Q`** to quit.

The script prints the detected plant-part counts and leaf-disease predictions in the terminal. It saves the latest report to `farm_report.json`.

### Run the other experiments

```bash
python live_detection.py
```

Runs continuous general-object detection using `yolo26n.pt`.

```bash
python counting.py
```

Runs a camera counting experiment using `sam_model.pt`. This script requests camera index `1`; change `cv2.VideoCapture(1)` to `cv2.VideoCapture(0)` if your camera is on index `0`.

```bash
python detector.py
```

Runs general-object detection on `photo.jpg`.

These scripts are separate experiments and do not all share the same behavior or model classes.

## Camera troubleshooting

- If the camera does not open, close apps that may already be using it.
- Try camera index `0` or `1` by changing the value passed to `cv2.VideoCapture(...)`.
- Confirm that your operating system has granted camera permission.
- On Linux, check that your user has permission to access the camera device.
- If the preview opens but frames fail to read, try another USB port or camera.

## Optional Flask message integration

`send_crop_message.py` posts JSON to this endpoint:

```text
http://192.168.4.2:5000/crop_message
```

That address is hard-coded in the script and is likely specific to a particular local network. To use the integration:

1. Run the matching Flask server on a reachable device.
2. Update `FLASK_SERVER` to the server's correct IP address or hostname.
3. Ensure the server exposes `POST /crop_message` and accepts a JSON body such as `{"message": "..."}`.
4. Check network/firewall settings.

If you do not have that Flask service running, message sending may fail; the camera-based detection workflow can still be tested, but the script will print a connection error when it attempts to send a message.

## Current limitations

- This is a **prototype**, not a complete autonomous rover application.
- The code in this repository processes camera frames; it does not itself control rover motors or implement farm navigation.
- Soil/environmental sensor integration (such as pH, NPK, soil moisture, temperature, or humidity) is not implemented in the scripts listed here.
- The fruit-ripeness model is commented out/disabled in the main workflow.
- Detection and disease classification depend on the training data and model weights. Lighting, camera quality, crop variety, and unfamiliar diseases can affect results.
- The scripts use relative paths, so run them from the project directory unless you update those paths.
- `capture.py` saves images under an `images/` directory; create that directory first if you use the script and it does not already exist.
- Review and test all outputs before using them to make real crop-treatment decisions.
